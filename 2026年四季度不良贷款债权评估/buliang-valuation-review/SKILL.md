# 不良债权价值分析报告：叙事解读与复核

## 交付目标与模式

默认交付**价值分析报告叙事解读**。按报告实际的价值形成过程，讲清“欠多少钱 → 靠什么回收 → 资产如何定价及扣减 → 谁补足缺口 → 最终金额如何算出”，让读者能够顺着叙述理解数字的来龙去脉，并查到每项比对所用文件及位置。不是报告摘要，也不是将审计问题清单改写成散文。

- 用户说“处理这份报告”“以同样逻辑解读”“生成叙事解读”：使用 [叙事写作指南](references/narrative-writing.md) 和 [叙事模板](assets/narrative_report_template.md)，配套 [核验范围与待补底稿](assets/review_scope_template.md)。延续会话中已认可的写法，重新读取目标户和指定版本。
- 用户明确要求正式复核意见、完整检查矩阵：增加 [正式复核模板](assets/review_report_template.md) 所需的表格，不能让其替代用户另行要求的叙事主文。
- 用户只问局部公式或事实：围绕该问题核验，不自动扩展成全户正式复核。

底层核验原则不因文风改变：事实是否吻合、假设怎样传导、案例与参数是否有据、计算与结论能否互证，必须分开判断。

## 范围、版本与输出

默认只读输入、不改写机构报告；用户明确要求改写时按授权保留原稿与变更记录。默认输出 `output/价值分析复核/{户号}_{户名}/`；**用户指定目录优先**，保留其目录根及既有分户组织方式，不再因默认路径另行请求确认。重生成时保留上一版主文及相关关键底稿，更新当前主文、引用、范围声明和日志，不能只删除“待核”字样。

项目资料映射见 [project-context.md](references/project-context.md)。以债务人全称关联，不按户号或sheet序号直接套数据；指定的修订版是本次对象，旧版只作明确标注的比较。文件名日期、正文署日、基准日、查询/走访日期分别记录。重复拷贝和同一提取表的两栏不算独立证据。

不移动原始归档、不改共享清单和台账。为阅读而解析DOCX内部条目、内存解密或短暂格式转换，与项目归档解包/搬迁分开；按用户现有授权执行前者，不借此启动归档阶段2。密码与读取限制见 [document-reading.md](references/document-reading.md)。

## 工作流程

### 1. 读取证据，先建立事实地图

按实际可得资料覆盖经办反馈、银行原件、法律尽调、机构报告。提取表与既有查册用于定位和对照，但要写清证据层次；未取得原件/经办口径不能声称四方已核齐。关键决定性事项回对应外部来源，不以机构转述代替已读尽调。

用 `scripts/extract_report.py` 提取可读报告和尽调，分别使用如 `09`、`DD09` 的key；JSON保留全文，MD用于定位。加密、扫描、嵌套表、图片公式等按读取指南处理，不能因抽取成功认定全文完整。`scripts/anchors.py` 的40母项及A/C子项召回只是导航；以 [review-checklist.md](references/review-checklist.md) 作覆盖索引，未完成的核验在底稿如实标记，不凑通过率。

建立“债权—责任主体—资产—受偿项”关联及版本/日期映射。债权本息费、旧贷/现贷、抵押/质押/保证/查封、历史清单/当前范围、土地/建筑/铺位统计单位先统一，再比较数值。

### 2. 交叉核对事实、假设及案例

读 [facts-assumptions-and-comparables.md](references/facts-assumptions-and-comparables.md)。债权、抵押人及其他责任主体、面积用途、权属占用、工程款、租赁税费、诉讼及还款逐项追溯。

- 工程款等：分别确认风险线索、存在事实、余额、法律优先性和可扣范围。先读尽调，再核机构是“无欠付”“未知所以未扣”还是已扣；未知金额保留X，不默填0，不把条件提示写成已确认欠付。说明核实后影响哪个资产净值及后续基数。
- 查册缺口：注明是本轮批量查册未匹配、证号未关联、OCR未解析，还是其他登记来源也未取得。尽调据他项证明记载登记时，与批量查册拼接核验，不因后者缺口说完全无登记依据；不按套数覆盖率直接打折估值。
- 经营/增信：登记存续不等于实际经营；无执行记录不等于有净资产；注册资本、持股比例、担保额度和监管约定不等于可回收现金。关联、夫妻及共用资产须核独立贡献，不能凭出现两次就认定重计，也不能凭一段防重声明宣布已去重。
- 案例：核具体位置/距离、用途、成交或挂牌、时点、权利及差异修正。匿名、期后或远距案例分别解释；不虚构公里数，不凭计算通过认定真实可比。
- 尽调也需前后核对：表与文、已补材料与旧缺口、主体身份、实缴状态等冲突保留双方位置，请责任方统一，不择取有利片段当确定事实。

### 3. 沿实际模型复算，区分结果与依据

读 [calculation-models.md](references/calculation-models.md)。核“印列公式 → 符号/单位 → 原始参数 → 实际代入 → 各步取整 → 汇总 → 两个回收率”，发现差异时说明其传播，不只检查最后加法。

模型已确认符合旧评分加权统一折现结构才用 `verify_calc.py`；其他逐步模型用 `verify_formulas.py`。输入、节点均绑定来源，明示单位、取整和容差。无法可靠编码的部分交逐步底稿并保留未验算范围。

分开重建案例/收益法示例、资产净变现、一般受偿、各保证人基数及最终封顶。**单项示例可复算不等于全户汇总已核实**；缺全项估价表时保留机构汇总为输入，说明缺哪一步。展示中间数与连续精度各算一条；小差额先核取整政策及原始精度，不自动定为重大差错。

敏感性只选实际存在的关键参数，标明经证据支持的条件值或纯压力假设、同一精度基准及联动。没有贴现结构不强加年限和利率；没有工程款金额不编情景区间。解释模型随抵押净值下降而机械增加一般评分回收的现象，不能视为独立增信。

### 4. 写叙事主文，把判断放在它影响数字的地方

先说明结论及主导来源，再沿报告真实的计算链层层推进。每个关键数交代“从哪来、如何形成、去向何处、证据和适用条件如何”。足额覆盖则解释封顶；无抵押、零贡献、收益法或不同保证基数均按实情改写，不套某一户公式。

主文用自然段和有信息量的过渡句；必要的公式、对比和情景用短表。核验发现紧跟相应取值说明，区分算术能否复现、参数有无依据、事实是否已核。正文使用轻量〔编号〕，具体文件/段落/单元格放文末来源索引，避免F/V/P/D编号和宽矩阵打断阅读。

完整数据留在底稿，不把每个小数和每套房堆进主文；但债权构成、资产分类规模、关键示例、全部计入的受偿路径及扣减/封顶必须串起来。未进入总额的中间测算说明去向，不能再扣或再加一次。

### 5. 交付与检查

叙事默认交付主文、来源索引、核验范围与待补、实际使用的证据及验算底稿；文件名和字段见写作指南。正式复核表按需增加，40项是底稿覆盖工具，不是默认主文结构。

六值状态为 `一致 / 差异 / 报告未披露 / 档案无法核验 / 不适用 / 待补`；待定位、加密未读、需OCR等为另列技术状态。用户补密码或资料后，重新读取并更新事实、引用、判断与受影响计算，仍未闭合的事项继续保留。

交付前检查链接、来源版本/身份、证据编号、单位和基数、公式/取整、正文与底稿一致性、遗留未读声明。记录原件读取与提取完整性的实际范围。结论不保证回收，不裁定权利效力、最终顺位或税负，不以压力演示出具替代估值；适用法律/税务结论须核有效原始依据及权威来源，不能凭模板推断。

## 工具入口

```bash
python3 scripts/extract_report.py --input "报告.docx" --out "指定分户输出目录" --key 09
python3 scripts/extract_report.py --input "可读尽调.docx" --out "指定分户输出目录" --key DD09
python3 scripts/anchors.py --evidence ".../evidence_09.json" --out ".../recall_09.json"
python3 scripts/verify_formulas.py --params ".../params_09.json" --out ".../verify_09.json" --sensitivity
```

原始加密OOXML不能直接交给当前提取脚本；读取指南提供处理条件。历史方法讨论见 [methodology.md](references/methodology.md)，旧江门表格样例见 [worked-example.md](references/worked-example.md)，都不替代当前证据、实际模型和叙事交付要求。
