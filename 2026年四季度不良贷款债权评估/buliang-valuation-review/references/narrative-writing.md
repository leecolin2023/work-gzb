# 价值分析报告叙事写作与交付

## 先确定读者要理解的主线

让读者能回答：债权是多少，主要依赖什么回收，报告如何把财产和主体变成金额，哪些金额可以复算，哪些事实和假设还需支持。首段给结论、基准日和主导回收路径；随后顺着价值形成过程讲，不逐章摘录报告，也不先列一屏风险等级和检查矩阵。

常见顺序是：当前债权及形成历史 → 谁承担责任及资产范围 → 权属/使用状态 → 案例或收益推算 → 折扣、税费、在先款 → 全项净值与优先受偿 → 借款人和保证人补充回收 → 费用/折现/封顶与回收率 → 关键依赖和待补。该顺序按实际模型调整，省去不适用的环节。

例如：

- 抵押净值高于债权：解释估价与处置条件，再说明债权封顶使一般及保证路径本次不新增贡献。100%是条件下覆盖，不是到账承诺，也不是担保人无责任。
- 无抵押、仅股权质押或保证：解释哪些权利存在、为何按零或非零，继而追索评分来源和实际可执行财产，不硬加“抵押处置”章节。
- 收益法：租金/合同及案例 → 面积和出租率 → 收入 → 运营成本 → 净收益 → 期限/报酬率/增长 → 单价 → 变现及净值。不要把资产报酬率当整笔债权贴现率。
- 多保证人：逐名写实际基数是否已扣借款人、赔偿或前名保证人，平行相加还是递减，以及上限。不能跨户复用“个人基数一定与法人相同”等结论。

## 段落怎样串起数字

每段围绕一个问题，用“数值及含义—形成过程—承接下一步—核实程度”展开，不必机械填四句话。过渡句应推进关系，例如“先统一清单范围，才能解释这个面积怎样进入估价”“正常单价还要经过变现和税费，才接近可分配现金”。

主文必须覆盖：

1. 本息费与截至日、旧贷/合同额度/现余额的关系；已还或已处置款不重计。
2. 主要责任主体及关联；资产用途、数量、面积和清单版本，解释一证多铺、土地分组、历史和现状差别。
3. 报告代表性单项的完整定价链；其他用途如何形成汇总，缺明细时在此停住“已核”范围。
4. 实际计入总额的各路径、费用和取整；中间股权评分等未计入的金额应明确为何不加，也不再扣。
5. 最终金额与本金/债权回收率的分母；摘要、正文、结论是否一致。

金额默认采用报告常用单位，单项估价必要时用元/㎡、元/月等，切换时明说；百分数、分值、权重和受偿率不混写。涉及大量资产时用分类小计串联，逐套明细放底稿。不是将全文所有数字逐个搬进主文。

正文可用加粗过渡句，表格只用于更清晰的并行比较、价值拆分或少量压力情景，不嵌套多级技术标题。正文优先写“尽调的走访记录”“股权表与后文说明”，具体P/T编号放来源注释。无需复述工具安装、解析过程、审阅时间线。

## 核验发现怎样嵌入故事

在读者走到相关数字时解释问题，不把所有异议堆到最后：

- 工商存续支撑经营分：说明注册状态和实际经营不同，再指出影响哪项率；不能仅写“参数依据不足”。
- 案例远、匿名、期后：说明价格来源怎样进入单价，需要补什么可比或时点依据；不推测距离和成交真实性。
- 可能欠工程款：先写尽调实际是条件风险还是已确认，再写报告是未定额扣除还是肯定无欠付，最后写查明后影响的资产和公式。未知金额用X，不编“假定欠500万元”冒充事实。
- 批量查册未覆盖但有登记证明：区分证据来源，说明须逐项拼接及刷新状态；不重复传播“没有任何登记证据”。
- 尽调前后不一：列双方位置与时点，回原件统一；“已直接读尽调”不代表尽调内容全部已独立证实。
- 资产同时用于抵押净值和一般评分：说明同源线索与独立净贡献待核，不能把出现两次直接变成重计定论。

用清楚的边界句：“这一段算术可以复现，但案例真实性未独立核实”“全户净值缺逐项税表，本次保留报告汇总为输入”。不能在后文将同一输入又称已全量核实。

## 取整及情景

分别报告展示中间数链和连续精度链。若单体取整之和不同于未取整合计，先核机构合计政策；未知原始精度时不以百元级差额直接定重大错误。

敏感性只在帮助理解关键依赖时展示。表内列“仅改变条件｜模型结果｜较同精度基准变化｜说明”，明确纯压力或有依据的条件，不统一使用“贴现前/后”列名。参数关联时说明其局限，不把多个上游影响简单叠加。

若资产净值下降、模型反而自动提高一般偿债贡献，解释这是剩余债权基数变大的机械结果，需要另核真实财产支撑。无可靠金额/区间的在先款只做符号传导。

## 来源和版本：数据要定位到文件的哪里

正文使用〔01〕等轻量标记；文末一条注释可含双方或多方来源，分别写明“谁的数据”和本次重算。注释数量随证据需要，不固定28/29条。

| 来源 | 最低定位要求 |
|---|---|
| Word | 完整文件路径/可点击链接＋该版本证据P####或T##-R##-C##；解释编号不是Word页码 |
| Excel | 文件路径＋工作表全名＋具体单元格/数据行区间＋字段含义；区分当前值、历史值、公式及缓存 |
| PDF | 文件路径＋实际页码/可读取行号，注明扫描OCR和未读范围 |
| 既有JSON/Markdown | 文件路径＋对象键/章节/行对象或证号；注明既有解析或二次成果 |
| 经办反馈 | 记录名称、日期、反馈主体及具体位置；未取得则明说，不虚构 |
| 分析者推导 | 双方源数据及算式/底稿节点，标“本次重算/纯压力/符号传导” |

示意：`〔05〕 价值分析报告的实际链接＋P…：单价与面积；结构表的实际链接＋工作表…!F…：当前面积，H…：旧值；本次相乘得…，见verify…节点。` 示例符号不直接作为真实引用交付。

同一事实在报告、银行提取表和尽调出现，先判断是否互相转述；读取原件后才能升级引用层级。解密、补资料或修订报告后，重新生成该来源索引，旧版本P/T编号不能沿用。更新正文、注释、源清单、范围表和受影响验算，清理过时“加密未读”声明，保留真实的原件/明细缺口。

## 默认交付包与验收

| 文件/内容 | 作用 |
|---|---|
| `{户号}_{简称}_价值分析报告叙事解读.md` | 主要阅读入口；正文、来源注释、少量必要小表及配套链接 |
| `{户号}_{简称}_核验范围与待补.md` | 资料实际读取层次、四方对照、受偿路径、重要差异与待补责任；40母项和适用子项的覆盖/未核状态放这里 |
| `evidence_{key}.json/.md` | 各实际读取版本的全文索引和定位；key区分VR/DD等，不互相覆盖 |
| `params_*.json`、`verify_*.json`或独立验算表 | 实际使用的分模型节点、来源、精度、比较及情景；无法程序复算的范围明示 |
| `source_manifest_*.json`或同等来源表 | 来源标识、路径、版本/日期、原始/提取/转述层次、已读范围；可计算时记录SHA256，不能把文件mtime当报告日期 |
| 范围/质量检查及工作记录 | 单位基数、引用链接、证据编号及数值检查结果；读取和事实缺口、重生成状态 |

资产多、用途或范围复杂时另交分类/逐项范围底稿；无需为不适用的模型生成空文件或复制别户脚本。正式复核意见只在请求时增加。用户要求Word或其他格式时按要求交付，保留可核来源；未指定格式时使用当前项目已认可的Markdown。

40项用作覆盖检查，不表示额外原件调查全做完。默认底稿可逐项记“本次未核/待补”及原因，不强制把每项审查扩成一个主文章节。正式全量复核才展开完整矩阵和差异台账。任何模式均不可宣称未完成项已通过。

交付前核对：叙述是否走完价值链；关键数是否有来源和去向；例子与全户界限；文件链接与版本编号；每个结果基数/单位/取整；压力与事实区分；读取层次与范围声明一致；当前稿无旧加密/未读声明残留。检查是底稿，不在主文前端展示技术清单。
