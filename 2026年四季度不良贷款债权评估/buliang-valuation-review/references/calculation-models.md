# 公式、代入与结果的独立验算

## 一、先识别模型，再决定怎么算

旧脚本 `verify_calc.py` 只覆盖“剩余债权×评分/100×权重，各项加总后统一折现”，旧schema兼容；可显式写 `model: legacy_score_discount`。不支持费用先扣、多名保证人递减基数、资产收益法等结构。不要把未知处置期/贴现率填0来伪装适配。

其他模型用 `verify_formulas.py` 的逐步公式台账。每个输入明确单位、来源与证据编号，每个节点记录报告印列公式、核验所用公式、代入、计算值、报告值、差额和容差。若印列公式与实际数值公式不同，分别建节点或独立记录差异，不默默修正报告。编写验算公式时独立从原文核对，不能为凑最终结果倒推参数。

## 二、三种错误分开查

1. 公式层：公式是否适用、符号和正负号正确，印列公式是否与模型描述一致。例如增减率、税费计税基数、先扣或后扣、年末/年中现金流、剩余年限、复利/单利。
2. 代入层：式中参数是否与前表、证据、主体和资产一致，元/万元、百分数/小数、年/月、平方米/套内面积是否统一。报告说取16却代入18，应按16独立重算并单列错代入。
分别保留 `reported_formula_text`（报告印列公式）和 `reported_substitution_text`（实际代入式）原文，程序输出会原样携带但不会自动理解文字。若代入式偏离原参数，建立两个独立节点：一项按印列公式和有证据参数重算，一项复现报告实际代入，比较差异。不能只抄报告错代入式再以算术一致证明代入正确。

3. 计算层：每一步乘除、加总、封顶、取整、折现/处置费及最终受偿率；原始精度与展示精度分开。先查局部计算，再查上游误差的总额传导。

`using_reported_intermediates` 用报告自身的上游展示值代入，帮助定位本步骤是否算错；`recomputed` 用连续独立重算的上游值。报告中间值导致除零等局部错误时，记录`local_error`，保留其他检查。两者都只验证输入公式的算术，不自动证明公式适用或代入抄录准确。未知原始精度时注明“展示数复算”，不把小差额自动升级为实质差错。

## 三、formula_graph schema

```json
{
  "model": "formula_graph",
  "inputs": {
    "area": {"value": "100", "unit": "㎡", "evidence": ["报告.docx:T01-R02-C02"]},
    "price": {"value": "10000", "unit": "元/㎡", "evidence": ["报告.docx:P0010"]}
  },
  "nodes": [
    {"id": "gross", "formula": "area * price", "unit": "元",
     "reported": "1000000", "tolerance": "0.01", "evidence": ["报告.docx:P0011"]}
  ],
  "result": "gross",
  "scenarios": [
    {"name": "单价下降10%（示意压力）", "reason": "参数依赖展示，不是市场取值或替代估值",
     "overrides": {"price": {"value": "9000", "basis": "stress", "evidence": ["压力假设：基准单价下降10%"]}}}
  ]
}
```

- 输入、节点ID为唯一标识符；节点按依赖顺序排列，不允许缺依赖、重复ID或循环。`result`必须指向计算节点。
- 推荐把小数作为字符串保存。内部用Decimal；四则、幂 `**`、括号、一元正负、`min/max` 可用，禁止任意函数/属性/脚本执行。不要用 `^` 表示幂，不支持百分号，应将5%输入为0.05。
- 所有输入与节点均必须有非空`unit`和`evidence`列表。来源引用须带文件/编号；分析者构造的公式/常量要明确标为“复核判断”，不能伪装成报告原文。
- 未知值不能写0或省略，脚本会拒绝；条件情景中的未知金额只有取得金额/可信区间后才能给数。只知道可能欠工程款时，保留符号传导，暂不执行含未知输入的节点。
- `reported`可省略，表示该节点仅作推导而没有报告对照值；有`reported`必须显式提供同单位绝对`tolerance`。不允许负容差，不能因用万元就沿用元单位容差。
- `round_to`可选，必须正数，如万元保留两位为0.01；只在报告真实取整节点设置。采用ROUND_HALF_UP。`raw`是取整前数，`recomputed`是进入后续节点的数。不设置则保留计算精度。
- `exceeds_tolerance`只是数值超容差，不叫业务重大差错。影响等级仍由证据、金额及受偿路径判断。
- `scenarios`只改inputs，不改计算逻辑；支持多输入联动。`basis=evidence`表示有实际证据，`basis=stress`表示纯压力假设，二者均需明确依据；覆盖基准参数后输出每个节点和总额变化。
- 脚本不自动校验量纲，也不核实证据内容。交付前人工核对单位变换、证据真实性、公式适用性和范围限制，不能仅凭程序成功就写“验算全部通过”。

## 四、各模型的核验重点

| 模型 | 节点与依据 |
|---|---|
| 资产变现 | 逐项面积×单价×变现率；在先款、税费和费用分别列，核费率是否已进入折扣及适用范围；按权利范围/剩余债权封顶 |
| 收益法 | 租金案例→有效毛收入→税费/运营费用→净收益→收益期/报酬率/增长率→资产单价；核收益期与土地/建筑期限，增长与报酬率及终值口径 |
| 基本率×调整系数 | 基本分与调整项合成受偿率，K×权重逐项求和，不强求原始分值满分100 |
| 多保证人 | 每个主体的基数与受偿率、与债务人/其他保证人的净资产重叠、剩余债权及能力上限；披露自然人与法人基数不同的依据 |
| 市场比较 | 每个案例原始价/租金→逐项修正→权重→结论；远距案例的地域差异修正与选择原因 |
| 现金流 | 各期可回款净额和时点→各期折现→加总；风险已在哪个参数体现，不能重复计风险或忽略时间风险 |

欠付工程款进入何处取决于模型和经核实权利范围。不能一律从整户债权额中减去：可能应减特定资产净变现额，之后再传导到剩余债权评分基数。须检查原模型是否已在工程成本、预计税费或变现折扣中考虑，防止重扣。

## 五、岭南水务示例的范围

`assets/params_lingnan_example.json`保留报告展示优先受偿440.47万元，演示多主体基数与3%处置费；另设独立收益法示例节点，报酬率4.95%仅用于资产收益法，不作为债权折现率。资产总净值缺逐项底稿，不能把收益法单套示例自动外推到全部商铺。

示例有意保留报告最终5972.81与展示输入重算5972.8172…的差额，用来追查取整链；容差仅是演示比较精度，不代表已确认业务实质影响。压力情景只说明参数依赖，不是经确认的替代取值。


## 六、怎样接入叙事主文

按实际价值链分别建立必要子模型：案例或收益法示例、单项变现税费、全项资产汇总、债权端各路径与最终封顶。只有单项明细时不得编造全项数；全项净值作为报告输入应在主文与底稿明确，不能以总额节点验算“通过”冒充逐项估价已核。

每个计入金额在主文交代来源和下一步去向。报告先列股权评分值后为防重取零、足额覆盖后保证不再新增等，要把取零/封顶节点讲清楚；不重复加回或扣除未进入结果的中间值。其他赔偿零、所得税暂列零和未知欠付工程款分别注明依据，未知金额不进入基准图。

展示链、连续精度链、银行元级精度分别保留；合计使用未取整数时，单体展示数之和的小差额先按实际精度解释。敏感性变化相对同一精度基准计算，不能混用机构展示总额与连续精度基准制造差额。

剩余债权评分模型中，抵押净值减少可能机械增大一般/保证基数；可推导局部传导，但须写清参数不变、封顶未触发等条件，不能把机械补回当独立现金来源。没有金额依据的工程款只保留X及受影响节点，不强制运行数字情景。正文中少量公式和短表即可，完整节点台账放底稿。
