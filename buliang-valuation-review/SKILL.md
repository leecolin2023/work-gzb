# 不良债权价值分析报告复核

## 目标与边界

回答四个相互衔接的问题：事实是否与经办及尽调掌握的情况一致；事实怎样进入估值假设和受偿路径；公式、参数与可比案例是否支撑估值；最终数额能否逐步复算并追溯。

只读原始报告、银行档案、经办材料、法律尽调和既有盘点成果。新增复核成果写在项目根目录 `output/价值分析复核/{户号}_{户名}/`。不删除、移动、重命名或解压原始资料；项目归档阶段2仍按既有暂停约定处理。复核意见可给出建议补充/修订段落；默认不直接改写机构报告，用户明确要求修改时按其授权处理，保留原稿与变更记录。不以敏感性情景出具替代估值。

## 执行流程

### 0. 确定资料范围与项目映射

读 `references/project-context.md`，按当前文件系统定位资料，不硬套旧路径。用户名＋债务人全称关联，避免户号交叉。列出实际版本、基准日、来源路径和缺失材料。

必须覆盖四类信息源：经办反馈/业务说明、银行原始档案、法律尽调、被复核报告。已有提取表、查册汇总和比对结论只是定位线索；0、空值、未解析、未覆盖不能互相替代。经办材料未提供时，完成独立核验并明确“经办口径未取得”，不能声称已核对四方。

### 1. 建立可追溯证据与候选定位

用 `scripts/extract_report.py` 提取报告；需要时也提取尽调，使用不同 `--key`，按“来源文件＋证据编号”引用。JSON为全文，MD仅供定位。扫描页、图片公式、OLE公式、缺失附表、复杂合并/嵌套表须回原文检查，文本抽取成功不代表内容完整。

运行 `scripts/anchors.py`：固定40项母清单，加A01~A06（事实/假设）和C01~C05（可比案例）子检查。关键词/正则召回只是导航，整行上下文保留原单元格编号，不代替判断。零召回记“待定位”，扩大检索并读全文/附表后才可判“报告未披露”。决定性依据在报告之外的检查项必须回相应外部材料。

### 2. L1 事实及假设交叉核对

完整走F01~F10及A01~A06，读 `references/facts-assumptions-and-comparables.md`。债权本金息费、债务人/抵押人/出质人/保证人、权属面积用途、占有租赁、工程进度、欠付工程款、税费及诉讼执行等，逐项列四方表述、证据时点、证据质量和模型影响。

遇到“经办称可能有欠付工程款，机构假设无欠付”：先定位尽调是否记载及其依据，再查报告的假设、参数及扣减依据，回合同、结算、付款、诉讼等核实。区分风险线索、存在事实、金额、法律优先性、可扣金额；不得把“可能”直接变成确定扣款。形成事实—假设差异、受影响公式、补料责任人及建议修订段落，有依据的事实进入复核意见及建议报告表述；金额未知时保留变量/附条件情景，不擅填0或固定金额。

### 3. L2 受偿来源及扣减闭环

走V01~V10。读取对应户查册分户报告、`audit_all.json`，必要时原始登记资料。建立债权—责任主体—资产—受偿项关联，核查应收账款等每类担保的登记/确权/结算/回款及按零或非零依据。按权证—铺位—面积—逐项估值勾稽，区分统计单位。

资产同时出现在两处是核验线索，只有相同价值或相同净资产贡献重复计入才认定重复计价。核查抵押物已贡献优先受偿后是否仍以全部资产支撑保证人评分。共同保证人、共用资产须在整包层面检查偿付能力与分配，单户材料不足时写待补，不确认全包去重完成。

### 4. L3 模型、公式、参数与案例核验

走P01~P12及C01~C05，读 `references/calculation-models.md`。先识别实际模型：资产变现/收益法、直接打分、基本回收率×调整系数、现金流、市场比较、多保证人或组合；不得按“综合因素分析法”名称强套同一个公式。

依次独立核对：印列公式是否适用 → 符号与单位 → 原始参数及证据 → 实际代入是否一致 → 每一步计算/取整 → 汇总/回收率 → 摘要及最终结论。记录上游误差传播，区分文字公式错误、错代入、算术错误、参数无依据、合理取整和口径差异。

可比案例核查位置/距离/商圈、业态、时点、租售类型、权利与交易条件、来源真实性、差异修正及权重。距离远不是自动不适用；要解释为何跨区域、当地案例不足原因及修正依据。匿名案例或只有“三级市场”不能视为已核实。最终单价/租金应能从案例调整计算复现。

验算路由：
- 已确认符合旧“评分×权重＋统一折现”结构，使用 `verify_calc.py`（旧schema兼容）。
- 其他可表达为逐步公式的模型，使用 `verify_formulas.py`；schema、用法见 calculation-models。每个输入/节点绑定证据，显式指定单位、取整和容差；节点按依赖顺序排列，未提供数据不得默认零。
- 复杂模型无法可靠编码时，提供逐步独立验算底稿并说明未验算范围，不生成“通过”结论。

敏感性按实际模型选参数，必要时说明相关参数联动；没有债权端折现不自动判错，不强加两年/5%。程序只判断数值是否超容差，不裁决事实正确性、法律效力、参数合理性或业务影响。

### 5. L4 披露与交付

走D01~D08，汇总经办/尽调/报告假设冲突及其传导，按影响排序。六值状态：`一致 / 差异 / 报告未披露 / 档案无法核验 / 不适用 / 待补`；“待定位”等技术定位状态单列，不混入六值结论。未证实风险可为事实口径差异或待补，不把风险存在等同法律优先权已成立。

用 `assets/review_report_template.md` 成文，含40项完成矩阵与适用子项、四方事实表、事实—假设—参数—结果链、价值来源矩阵、验算记录、可比案例表、建议修订文字和待补材料。提供证据索引、召回、参数、验算、敏感性；实际有工具则交付附件，否则给本地链接。日志仅写复核输出目录。未完成的核验与外部材料缺口明确披露，不凑出完整复核。

## 资源与用法

- `references/review-checklist.md`：40项母清单及状态；全部走完，不适用须说明原因。
- `references/facts-assumptions-and-comparables.md`：A/C子检查、经办事实冲突、案例适用性，相关复核必读。
- `references/calculation-models.md`：多模型验算schema和独立核验方法，L3必读。
- `references/methodology.md`：分析口径与项目待确认建议，不是通用规范。
- `references/project-context.md`：旧项目背景及当前目录映射。
- `references/worked-example.md`：江门佰富历史样例，数字与争议判断不得直接用于其他户。
- `assets/params_example.json`：旧模型示例；`assets/params_lingnan_example.json`：岭南多主体公式模型示例（仅作验算演示，不是完整估值底稿）。

```bash
python3 scripts/extract_report.py --input "报告.docx" --out "项目根/output/价值分析复核/05_岭南水务" --key 05
python3 scripts/anchors.py --evidence ".../evidence_05.json" --out ".../recall_05.json"
python3 scripts/anchors.py --list
python3 scripts/verify_formulas.py --params ".../params_05.json" --out ".../verify_05.json" --sensitivity
# 旧模型确认适用后：
python3 scripts/verify_calc.py --params ".../params_07.json" --out ".../verify_07.json" --sensitivity
```

复核中的“一致”仅指指定事实与证据吻合，不代表权利有效、债权存续或金额一定实现。查册覆盖率和收益率范围等项目建议须标“建议值，待确认”，不得据其自动判错。涉及税法/法律适用结论须回有效原始依据及最新权威来源；不凭模板作法律裁定。
