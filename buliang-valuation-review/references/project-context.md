## 二、证据源优先级

| 层 | 证据 | 用途 |
|---|---|---|
| 1 | 不动产登记簿／查册表 | 抵押权设立、顺位、查封、面积 |
| 2 | 他项权证／权证扫描 OCR | 权属、证号 |
| 3 | 判决书／裁定／执行文书／和解协议 | 债权金额、判项、受偿权、执行进展 |
| 4 | 借款／担保合同、放款凭证、还款流水 | 债权形成与余额 |
| 5 | 法律尽调意见 | 律师明示的风险与资料缺口 |
| 6 | 拟转让清单、银行反馈表、结构包抵押物清单 | 户级业务事实与银行口径 |
| 7 | 全户查册核对总报告及分户报告 | 已结构化的查册结论（覆盖率、查封、资产性质冲突） |
| 8 | 手工抄录／二次整理表 | **不作基准**，仅作线索 |

报告自述与上层证据冲突时，以上层为准，并在差异清单中列双方位置。

## 五、只读边界（硬性）

项目已确立两阶段流程，**阶段 2（解压、临时目录、移动归档、补 3-文件溯源台账）在用户解除暂缓前不得执行**。本 skill 遵守：

- 全程只读输入报告与档案；不修改外部价值分析报告、银行档案、共享资料、`资料清单.xlsx`、`四季度资产包_总台账.xlsx`、查册盘点成果。
- 新增文件只允许写在 `output/价值分析复核/` 下。
- 不删除、不重命名、不解压任何原始资料。
- 新资料入库仍按项目约定：存入 `源包库/` 并同步更新 `资料清单.xlsx`，二者是同一个动作。

## 六、报告结构差异预期

其他户的价值分析报告可能：章节数与顺序不同、摘要与正文合并、无评分表（改用资产端逐套估值）、采用市场法或现金流法、价值类型不同、附表位置不同、docx/doc/PDF/扫描件混合。

**应对**：一律先经 `scripts/extract_report.py` 归一化为证据索引，再按 `scripts/anchors.py` 的检查项与语义锚点召回。不得假设章节编号、表格位置或固定关键词。扫描件无文本层时，标注技术定位状态「需 OCR」并列入待补，不得据目录或封面推断内容。

## 七、与其他 skill 的联动

- `buliang-asset-audit`：资料齐全度盘点。复核 L1 的 `档案无法核验` 项可回查其单户台账；其 `references/project-context.md` 与各户目录命名差异说明同样适用。
- 本 skill 输出的高影响差异与待补材料，可作为下一轮资料补料的输入，但**不自动写回**任何清单或台账。
